# YouTube Ledger

A local YouTube usage tracker for **Chrome and Firefox**. Records video titles, timestamps and elapsed playback time; separates foreground watching, background audio, silent playback and browsing; and hides recommendations until you reveal them.

## Install

Download the **0.16.24** package for your browser below. These ZIPs are ready
to install; no build tools are needed. For development, clone the repository
and follow [Build and test](#build-and-test).

### Chrome

1. Download [the Chrome ZIP](https://github.com/cabe9/youtube-ledger/releases/download/v0.16.24/youtube-ledger-chrome-store-0.16.24.zip) and extract it to a permanent folder.
2. Open `chrome://extensions` and enable **Developer mode**.
3. Click **Load unpacked** and select the extracted folder.
4. Pin YouTube Ledger, refresh existing YouTube tabs, and click the extension icon for the dashboard.

Keep the folder in place. The installation survives browser restarts. To update, replace files in the same folder, click **Reload** in the extensions page, and refresh YouTube and the dashboard. Moving the folder can change the extension identity. This is not a Chrome Web Store installation.

### Firefox

1. Download and extract [the Firefox ZIP](https://github.com/cabe9/youtube-ledger/releases/download/v0.16.24/youtube-ledger-firefox-store-0.16.24.zip).
2. Open `about:debugging#/runtime/this-firefox`.
3. Click **Load Temporary Add-on** and select the extracted `manifest.json`.
4. Refresh YouTube tabs and open YouTube Ledger from the extension toolbar.

Temporary installations stop at browser restart. A durable Firefox installation requires Mozilla signing, which has not been performed. Export history before removing a temporary installation; do not rely on it surviving removal.

## What it does

- Records a detailed viewing history: which videos you watched, when you watched them, how long they played, and whether playback was in the foreground, background audio, or silent in the background.
- Ignores paused background tabs; actual background playback still counts.
- Lets you assign Work, Learning, Leisure, Background, Unplanned or Unsorted labels to a video's day. Conflicting older labels appear as Mixed until you choose a label.
- Hides the Home feed, related-video sidebar and matching end-screen suggestions by default. Search and subscriptions remain available.
- Places a compact **Show/Hide recommendations** eye icon immediately beside desktop YouTube's search bar, aligned with the input even when autocomplete expands. A crossed-out eye means recommendations are hidden; an open eye means they are shown. Hover for the action, or use the keyboard and screen-reader label. Each navigation resets recommendations to hidden. Reinjecting the control retires its previous instance and removes leftover eye buttons, preventing duplicates after extension reloads.
- Records Show clicks and recommendations detected in the viewport as distinct events. These are not network-request counts or proof of attention.
- Includes daily totals, a recommendation timeline, a retrowave dashboard, JSON export and an LLM review-prompt export.
- Creates local channel groups, with channels belonging to one or more groups. Add channels from the Groups tab or the **Add to group** button on supported desktop YouTube channel and watch pages.

## Channel groups

Open **Groups** in the Ledger dashboard to create or rename groups. Select a group, enter a YouTube channel URL, `@handle`, or `UC…` channel ID, and click **Add channel**. On desktop YouTube channel and watch pages, **Add to group** opens a picker: select any groups or create a new group containing that channel. Typing in the picker does not trigger YouTube's player shortcuts; Space, Tab, Enter, and Escape retain their normal menu behavior. Changes save automatically in the current browser profile.

Channels are identified by their stable YouTube channel ID. Removing a channel from one group leaves its other memberships intact. Groups are separate from YouTube's Subscribe button; group actions do not subscribe or unsubscribe you. You can remove memberships or delete groups from the dashboard without deleting viewing history. Group editing remains available while activity tracking is paused.

When you add a channel, Ledger requests the public YouTube channel or video page to resolve the creator's ID and name. No API key, account access, backend, or new host permission is used. If a video cannot be resolved, add its channel URL from Groups instead. The in-page control currently targets desktop channel and watch pages; use the dashboard for other layouts.

Desktop YouTube now has a **Groups** section immediately above the subscribed-channel list when that native section is available. Select a group to see its uploads newest first at `/feed/subscriptions#ledger-group=<id>`. The collapsed sidebar has a compact Groups entry. The feed follows the selected Ledger theme. Click a thumbnail or title to watch; click the creator’s name or initial to open their channel. Expand the channel count to see all members and any refresh errors. The expanded and collapsed Groups sidebar backgrounds are transparent, with YouTube text colors and translucent hover/selection highlights. Each group has an outline icon. Hover or focus a sidebar row and choose **Edit icon**, or use **Edit icon** in the dashboard group controls, to choose from 16 symbols, paste a single emoji, or upload a PNG, JPG, WebP, or animated GIF. Still images up to 10 MB are resized to fit within 128 × 128 pixels; GIFs up to 512 KB retain their original bytes. Larger GIFs up to 10 MB resize locally to fit the saved-image limit, preserving animation, frame timing and loop behavior; complex animations (over 400 frames, 2048 pixels per side or 100 million decoded pixels) require shortening first. Uploads use FileReader strings so they also work inside Firefox’s content-script security boundary. Choose **Save icon** to apply the preview, or **Remove image** to return to the folder icon. Images are stored locally with group data, with a 2 MB combined limit on stored image data; no image is uploaded to a server. Icons save locally and update across open tabs without reloading the feed. Existing groups use a folder by default. The row’s **Manage group** menu opens controls for renaming, removing members, adding multiple channels and moving a group up or down. The Groups header can collapse the list; its + button opens bulk selection. Reloading the group view retires old observers, timers, listeners and pending UI updates, then removes leftover navigation, feed and style nodes. The first group click uses YouTube’s native subscriptions navigation and keeps the group view visible while it loads, including clicks before the native guide links are ready. Group switches and Back/Forward update the existing page without reloading YouTube. Browser Back restores the group’s loaded range and scroll position. If YouTube rebuilds its page area, Ledger reattaches the existing feed before the next paint without restarting the fetch. Refreshes retain unchanged video cards and thumbnails.

The feed requests public YouTube Atom/RSS uploads without account cookies or an API key. If an RSS request returns HTTP 404 or a supported server error without Retry-After, Ledger tries one public uploads-list page through the same queue, at least ten seconds after the preceding request. A successful fallback supplies up to 30 dated videos from the first page without following continuations; existing cached uploads remain. This includes whichever uploads YouTube exposes there, rather than only its Videos tab. Undated entries are not given invented release dates. A note identifies recovered uploads, and ~ marks rounded upload ages or view counts. Exact cached publication times are preserved. Fallback channels refresh automatically at most every two hours and retry RSS after 24 hours; manual refresh keeps the existing 60-second floor. Failure of both sources counts toward the shared failure guard. HTTP 403/429, Retry-After and already active cooldowns prevent fallback requests. Both attempts appear in Settings → YouTube requests. Feed, video-detail and channel lookups share one paced queue per browser: foreground requests start at least two seconds apart, and background requests at least ten seconds apart. A local cache keeps previously discovered uploads; there is no three-month cutoff. YouTube generally exposes only its 15 most recent uploads per channel, so this is a recent-upload view, not a full archive. Ledger retains up to 250 uploads per channel and 5,000 overall, favoring newer releases. On browsers with a fixed local-storage quota, refreshes also leave up to 2 MiB (at most a quarter of the quota) for recording. Storage pressure can evict older upload metadata earlier; history, notes, groups, icons and watch state are not automatically removed. Evicted uploads that have left RSS may not be recoverable without a backup. Channels removed from all groups are pruned from the feed cache. Opening a group refreshes feeds older than 15 minutes; the open view also checks every 15 minutes. Manual refresh has a 60-second request floor for healthy feeds and respects failure cooldowns. Closed-browser gaps can miss uploads. Failures retain available cached entries and identify affected channels. While a YouTube tab is open, including a background tab, Ledger also checks saved groups after 30–60 seconds and every 15 minutes, reusing inactive-group uploads for two hours and checking up to 200 due channels per sweep (oldest checks first). Unfinished group refreshes continue at background priority after leaving the group. Background requests stop when all YouTube tabs close or the Settings → Refresh subscription groups in background option is turned off. This option starts enabled; it does not disable refreshes in a visible group. Browser tab suspension or computer sleep can delay checks. Warm channels and active global cooldowns are skipped before creating background work. Failed feeds back off from 15 minutes to two hours without immediate retries. Scattered HTTP 404 responses among successful feed checks only delay retries for the affected channels. Automatic lookups pause after three distinct non-404 feed failures within five minutes, or three failed feeds in that window without a successful feed check. Paced manual channel additions remain available during these precautionary pauses. HTTP 403/429 responses or server Retry-After instructions pause all lookups, including manual additions. The feed shows the reason and retry time while preserving cached videos. This keeps sidebar new-upload dots useful without requiring every group to be opened. No requests run when the browser is closed.

Daily JSON and LLM exports include each visit’s `source` and combined videos’ `sources`, including per-source activity seconds. Group launches use short-lived, browser-session link tokens bound to the group name and listed video IDs, including links opened in a new tab. Supported recommendation, search, subscription, Watch Later and channel links retain their observed source when opened in a new tab, including modifier/middle clicks and context-menu links. A supported native autoplay transition is recorded separately as **Autoplay**, only when an ended video, enabled autoplay control and matching next-video link establish the destination. Other entry points remain **Unknown**. Being a member of a group never by itself classifies a watch as a group visit. Group names are snapshots, so later renaming or deleting a group does not rewrite history.

Recent releases show relative timestamps such as “2 hours ago” or “3 days ago”, updating each minute. Hover over a timestamp for the exact local publication date and time. Older releases show their date.

It supports touch, keyboard arrows, Escape, and outside-click dismissal. Marking Unwatched starts fresh coverage on the next playback. Upload date starts newest first, Views and Views per hour start highest first, and Video length starts shortest first. Sorting saves per group; the query and scroll position stay in the tab session. Watch-state changes, hiding/restoring, channel removals and group deletions offer Undo for up to five minutes in the current browser session. Undo rejects conflicting newer changes instead of overwriting them, preserves newer playback ranges, and compresses larger snapshots locally. Older temporary records are evicted to bound storage. Initial group/queue fragments survive YouTube’s canonical URL replacement. ## Privacy and daily review

Read the [privacy policy](https://cabe9.github.io/youtube-ledger/privacy.html) for information about local data handling, permissions, exports, retention, and deletion.

No account, API key or external service is required. Usage data stays in your browser profile. The extension does not upload history, record screenshots/audio, or read unrelated websites. Private/incognito use is disabled. Chrome and Firefox histories are separate; automatic synchronization is not implemented; full backups support manual migration.

The source and ZIPs contain no viewing history. Your own exports do contain personal history. Export before uninstalling if you want to keep your data.

Add notes about your day, label videos, and export an LLM review prompt to use with your preferred LLM. No automatic LLM connection is configured. The export asks for an explicit scoring rubric and uses your notes for context. The Review instructions field in Settings starts blank; you can add directions for the AI reviewing your exported activity. The old built-in preference is cleared when settings are read; other custom prompts are preserved.

## How tracking works

Foreground records playback while the YouTube page has focus. Background audio records unmuted background playback. Firefox native picture-in-picture may count as background. Multiple simultaneous videos accumulate independently. First/last timestamps can span gaps; use playback totals for duration.

Playback is sampled roughly once a second and normally saved in batches of five samples. Gaps longer than five seconds are excluded. Saves are acknowledged; failed batches retry every five seconds while the YouTube tab remains open. A receipt stored with each session makes a lost reply safe to retry, including after a service-worker restart. Each tab holds at most 300 unsaved samples, about five minutes at normal sampling. If storage fills, Ledger first reclaims upload metadata. If saving still fails, the YouTube page shows a notice, the toolbar badge shows !, and the dashboard shows a recording warning. Free space by backing up and deleting older history; keep affected tabs open for retry. An overflow notice means some activity could not be saved. The dashboard warning stays until dismissed so a successful later save cannot conceal a possible gap. Closing or reloading a tab, reloading the extension, or a crash can still lose buffered activity; refresh YouTube after an extension update. Paused includes buffering and seeking. Old sessions may retain background paused time; original data is preserved as `rawSessions`, while the dashboard uses grouped activity. Use grouped activity for totals and raw sessions for detail. New raw sessions include observed wall-clock playback intervals, keeping pauses separate; at most 2,048 disjoint intervals are retained per session/day. These intervals and retry receipts round-trip through full backups. Older records are preserved without inventing playback intervals. Operational warnings, reserved storage padding and transient retry buffers are not included in backups.

Ads, Shorts metadata, mobile selectors, and recommendation visibility are best-effort and may need adjustment when YouTube changes its layout. The header control waits for a supported desktop header rather than displaying a floating overlay.

## GitHub-only experiment

An optional [experimental account-history build](experimental/account-history/README.md) can recover recent activity from other devices without opening tabs. It is labeled **YouTube Ledger Experimental**. After opt-in, opening History checks at most once daily; a manual check can read up to three batches, with a 20-minute cooldown and progress indicator. Coverage remains partial. This unofficial method has no approval from Google.

This feature is physically absent from standard/store extension packages: no reader, controls, extra permission, report fields, or feature references. The default build uses only standard source; `python3 build.py --channel experimental` explicitly applies the isolated experiment. Experimental packages must not be submitted to browser stores. Existing store/direct-tracking behavior is unchanged.

## Build and test

Requires Python 3 for packaging and Node.js 22 or later for the full test tooling. On Windows, use `py -3` instead of `python3` when using the Python launcher. No Node.js dependencies are needed just to build the extension. The extension makes no runtime package downloads. The pinned GIF codecs are bundled locally with their licenses; `python3 scripts/build-gif-codec.py` reproduces that bundle from integrity-checked source packages.

```sh
python3 build.py
python3 package-check.py
npm install
npm test
npx playwright install chromium
npm run test:ui
npm run test:navigation
npm run test:recommendations
npm run test:chrome
npm run test:groups
npm run test:group-images
npm run test:feeds
npm run test:features
```

Installable downloads live in [GitHub Releases](https://github.com/cabe9/youtube-ledger/releases/latest); generated ZIPs are not committed to the source tree.

`build.py` defaults to store packages, cleans `dist/chrome` and `dist/firefox`, and produces `youtube-ledger-{browser}-store-0.16.24.zip`. Experimental output goes under `dist/experimental/` with explicitly named `-experimental-` ZIPs. `package-check.py` scans both store archives for excluded code, UI, permissions and references, and checks that stale output files cannot leak into them. UI and recommendation checks use installed Google Chrome. The Chrome integration check uses Playwright's Chrome for Testing in a disposable profile, with an actual unpacked extension and controlled YouTube HTML/media fixtures. After building, `npm run test:group-images:firefox` tests file uploads with the actual extension on live YouTube in a disposable Firefox profile, including animated GIFs, still-image resizing, rejection of invalid/oversize files, and reload persistence. It uses WebDriver BiDi (Node 22+ and Firefox 140+); `FIREFOX_BIN` can select the Firefox executable.

Verified: aggregation, paused-tab exclusion, recommendation event storage, UI behavior, content-script injection, real media playback tracking, recommendation controls, purpose labels, pause, data persistence across a full Chrome restart, and worker messaging after restart. Live YouTube layouts and the user's exact theme still require real-world validation.
